# Email Setup

## Default behaviour (no configuration)

If SMTP credentials are not configured, CAPEXX still generates the complete
professional email and displays:

```
EMAIL GENERATED — DELIVERY NOT CONFIGURED
```

CAPEXX never claims an email was sent unless the SMTP server confirms
delivery.

## Enabling real delivery

Provide SMTP settings via **Streamlit Secrets** (recommended) or environment
variables. Never commit credentials to GitHub.

### `.streamlit/secrets.toml` (local development)

```toml
[smtp]
smtp_host = "smtp.gmail.com"
smtp_port = "587"
smtp_user = "your-address@example.com"
smtp_password = "an-app-password"
smtp_from = "CAPEXX AI Agent"
```

### Environment variables

```
CAPEXX_SMTP_HOST=smtp.gmail.com
CAPEXX_SMTP_PORT=587
CAPEXX_SMTP_USER=your-address@example.com
CAPEXX_SMTP_PASSWORD=an-app-password
CAPEXX_SMTP_FROM=CAPEXX AI Agent
```

### Streamlit Cloud

Add the same keys under **Settings → Secrets** for the deployed app.

## How a send works

1. The email subject/body is always generated by the CAPEXX report engine.
2. `try_send_email()` reads the SMTP config.
3. On success the app shows a confirmation derived from the server response
   (`confirmed=True`).
4. On any failure the app shows the error and reverts to
   **EMAIL GENERATED — DELIVERY NOT CONFIGURED**.

## Notes

- For Gmail you must use an App Password (2-step verification required) or an
  OAuth flow - standard Gmail passwords are rejected.
- Port 465 uses implicit TLS; all other ports attempt STARTTLS.
- This is a demonstration-safe implementation; for production use a managed
  email API (e.g. SES, SendGrid) and never store passwords in source code.
